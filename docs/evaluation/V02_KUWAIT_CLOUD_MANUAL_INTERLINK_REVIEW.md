# Kuwait Cloud-Based v0.2 interlink review

- Scope: 28 Kuwait `Cloud-Based` v0.2 reports from `v02_reports_test_interlinking.csv`.
- Evidence: report fields read from the configured Ken Consulting CMS API.
- Review rule: recommend an inline link only when the source paragraph already supports the target concept. Existing prose is preferred. A copy insertion must be small, factual and locally supported.
- Excluded placements: headings, lists, tables, scope, methodology and table of contents.

## Result

15 inline opportunities survived manual review:

- 4 are compatible with the current deterministic context-anchor rule.
- 1 uses a clear existing contextual phrase but needs an editorial anchor override.
- 10 require a small, reviewable sentence insertion.
- 14 of the 28 reports qualify as source pages; the other 14 should receive no forced inline link from this corpus.

The literal phrase scan found 19 directed pairs. Most were rejected because the phrase appeared in the source report's own title, was too vague, or referred to a different application of the same technology.

## Machine matches that should be rejected

| Match pattern | Examples | Why reject |
|---|---|---|
| Anchor taken from the source's own market title | “Fraud Detection Platforms”, “Customer Journey”, “Testing Platforms”, “Automation Platforms” | Redirecting part of the source's self-identification to another report mislabels the source and confuses the reader. |
| Anchor names only the buyer environment | “digital banking” from Digital Lending or Financial Risk Management to the fraud-detection report | “Digital banking” does not tell the reader that the destination is specifically about fraud detection. |
| Same words, different application | “Orchestration Platforms” in supply-chain orchestration pointing to customer-journey orchestration | Supply-chain and customer-journey orchestration solve different problems. |
| Generic technology phrase | “Testing Platforms”, “Analytics Platforms”, “Automation Platforms” | The wording is too broad to predict the destination accurately. |
| Negative or disclaimer paragraph | “predictive AI” inside “does not establish a separately verified…revenue stream” | It is technically related but a poor engagement placement and gives the link a defensive, low-value context. Use the positive market-overview insertion in recommendation 15 instead. |
| Wrong vertical | “fraud detection” in a banking paragraph pointing to Retail POS Fraud Detection | The source paragraph establishes banking, not retail point-of-sale activity. |

## Implementation guardrails

1. Current-rule links may be proposed automatically, but still require normal review.
2. Sentence insertions are editorial copy changes. Keep them in a separate approval class; do not let the engine silently rewrite prose.
3. Limit a paragraph to one new inline link.
4. Prefer the first useful explanatory mention, not the title sentence, FAQ boilerplate, a heading, list or table.
5. If the exact proposed sentence is absent after a content refresh, invalidate the recommendation instead of searching for a looser placement.
6. For other same-market reports without inline context, use a related-reports module rather than manufacturing prose.
