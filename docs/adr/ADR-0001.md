# ADR-0001 — Monorepo layout with a single multi-root Python distribution

- **Status:** Accepted
- **Date:** 2026-10-13
- **Phase:** 0

## Context

TRD.md §4 mandates a monorepo with `apps/web`, `apps/api`, `agents/*`, `services/*`, `tools/*`,
`skills/*`, `workflows`, `contracts`, `evals`, `policies`, `migrations`, `tests` and `infrastructure`.

The Python code under `apps/api`, `services`, `agents` and `contracts` must import across those roots.
The development machine has neither poetry nor uv, and plain pip has no workspace path-dependency
mechanism: a pyproject per root that declares `dependencies = ["ken-core"]` makes pip look on PyPI and fail.

## Decision

One distribution, `ken-interlink`, installed once with `pip install -e ".[dev]"`. Setuptools discovers
packages across four roots:

```toml
[tool.setuptools.packages.find]
where = ["contracts/python", "services", "apps/api", "agents"]
include = ["ken_*"]
```

Each root contributes exactly one uniquely-named top-level package:

| Import | Path | Arrives |
|---|---|---|
| `ken_contracts` | `contracts/python/ken_contracts` | Phase 0 |
| `ken_core` | `services/ken_core` | Phase 0 |
| `ken_api` | `apps/api/ken_api` | Phase 0 |
| `ken_agents` | `agents/ken_agents` | Phase 0 |
| `ken_services` | `services/ken_services` | Phase 1 |
| `ken_tools` | `tools/ken_tools` | Phase 3 |

TRD §4 directories with no Phase 0 code (`tools/`, `skills/`, `evals/`, `workflows/`) hold only a
README naming the phase they arrive in. Git cannot track empty directories, so a README is the only
honest way to reserve the name.

## Alternatives rejected

- **Separate pyproject per root.** No path-dependency mechanism without poetry/uv workspaces.
- **Single `src/ken/{api,agents,...}` root.** Clean packaging, but visibly contradicts TRD §4.
- **PEP 420 namespace `ken.*` across roots.** Editable installs with a shared namespace across
  multiple roots are fragile; the debugging cost exceeds the cosmetic benefit.
- **requirements.txt only.** Leaves packages uninstallable, forcing `PYTHONPATH` hacks everywhere.

## Consequences

- Verified on 2026-10-13: all four packages import and resolve to their source paths.
- Every command must use `.venv/bin/...`, because the system `python3` is 3.9 and SQLAlchemy 2.1
  requires 3.11+. `requires-python = ">=3.12,<3.13"` enforces this at install time.
- Non-editable builds (`pip install .`, wheels) across four roots are a known setuptools rough
  edge and are **not yet verified**. Nothing in Phase 0 depends on a built artifact; verify before
  anything does.
