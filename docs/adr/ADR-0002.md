# ADR-0002 — Colima as the local container runtime

- **Status:** Accepted (installed with explicit user approval, 2026-10-13)
- **Phase:** 0

## Context

TRD.md §21 requires a Docker Compose stack, and IMPLEMENTATION_PLAN.md's Phase 0 exit criterion is
"`docker compose up` starts the local stack". The development machine had no container runtime at all.

## Decision

Install **Colima** with the **Docker CLI** and the **Docker Compose plugin**, via Homebrew.

| Component | Version installed | Licence |
|---|---|---|
| colima | 0.10.3 | MIT |
| docker (CLI) | 29.9.0 | Apache-2.0 |
| docker-compose | 5.6.0 | Apache-2.0 |

The VM runs with 2 CPU, 4 GiB RAM and a 20 GiB disk. The Compose plugin is registered through
`cliPluginsExtraDirs` in `~/.docker/config.json` (that file did not previously exist).

## Alternatives rejected

- **Docker Desktop** — requires a paid subscription for commercial use above small-business thresholds.
- **OrbStack** — requires a paid licence for commercial use.
- Both sit badly with the project's free/self-hosted constraint (CLAUDE.md constraints 1–3).
- **Podman** — viable and free, but its Compose compatibility layer adds friction against a
  Compose-first spec.

## Consequences

- `docker compose up` is genuinely verifiable, not merely authored.
- On macOS a Linux VM has **no Metal/GPU access**, which is why the host Ollama remains the preferred
  model service (ADR-0007).
- Colima is not started at login automatically. `colima start` is required after a reboot.
