# ADR-0005 — The worker is a tick loop, not a queue consumer; heavy dependencies are deferred

- **Status:** Accepted
- **Phase:** 0

## Context

TRD.md §21 requires a `worker` service. The Phase 0 brief forbids Celery, Redis, Kafka and Temporal,
and Phase 0 has no work to schedule. TRD.md §2 also names LangGraph, Playwright and Scrapy, while the
Phase 0 brief says "no agent intelligence".

## Decision — the worker

`agents/ken_agents/worker.py` (`python -m ken_agents.worker`) is a plain `asyncio` loop that **owns no
queue and makes no decisions**. Each tick it runs the readiness probes, emits one structured heartbeat
log line, and appends one `worker.heartbeat` row to `events` (since Phase 1: on the first tick and
then only when the aggregate status changes; see the amendment below). It handles SIGTERM/SIGINT gracefully and
supports `--once` for deterministic tests.

This proves database writes work outside the request path and gives the process that will host the
Phase 1 crawl scheduler and the Phase 4 LangGraph runner without restructuring.

**Explicitly forbidden:** an in-process `asyncio.Queue` "job system". That would be shadow
infrastructure. TRD §15 allows a PostgreSQL-backed event bus; when real work arrives it is designed
deliberately, not grown by accident.

## Decision — deferred dependencies

| Dependency | Arrives | Why not now |
|---|---|---|
| `langgraph` | Phase 4 | No graph to run; an unused dependency tree |
| `pgvector` (Python) | Phase 2 | No vector column exists (ADR-0003) |
| `beautifulsoup4` | Phase 1 | No crawler yet |
| `scrapy` | only if scale warrants (TRD §2) | `httpx` + `beautifulsoup4` first |
| `playwright` | Phase 6 | ~400 MB browser download for nothing |
| `opentelemetry-*` | Phase 7+ | TRD §2 says "supported", not required; the `trace_id`/`span_id`/`request_id` log fields are already reserved |
| `langfuse`, `smolagents` | ADR-gated | TRD §2: do not stack agent frameworks without an ADR |

The TRD §4 directories they belong to (`tools/`, `skills/`, `evals/`, `workflows/`) exist now as
READMEs that name their phase.

## Amendment — Phase 1 (2026-10-13)

From Phase 1 the `events` table carries real domain events (`page.created`, `crawl.completed`, …). A
heartbeat row every 30 s per worker (~2,880 a day, with no retention) would bury them (Phase 0 QA L4).
The worker now **persists** a heartbeat on its first tick and then **only when the aggregate readiness
status changes**. A failed write is retried on the next tick. The structured heartbeat **log line** is
still emitted on every tick, and liveness is observed from logs. The worker still owns no queue. Crawls
and imports run from the CLI, not from the worker.
